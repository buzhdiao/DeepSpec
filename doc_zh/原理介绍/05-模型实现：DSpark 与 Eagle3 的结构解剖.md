# 第五章　模型实现：DSpark 与 Eagle3 的结构解剖

## 5.1 复用骨干配置的派生式建模

DeepSpec 的草稿模型不是从零定义的架构，而是"目标模型的家族结构加草稿专有字段"的派生体。以 DSpark 为例，deepspec/modeling/dspark/qwen3/config.py 的配置构造函数先深拷贝目标模型的配置对象，保留全部生成相关超参（终止符、起始符、最大位置数、旋转编码设置等），只把解码层数换成草稿的层数，再写入草稿专有的字段：块长、锚点数、层取点、马尔可夫头配置、置信度头配置。深拷贝而非共享是刻意的——草稿与目标各持一份配置对象，后续任何一方的就地修改都不会污染另一方。

派生式设计有三重收益。其一，家族一致性自动成立：草稿的词表大小、隐藏维度、注意力头结构、旋转编码函数全部与目标对齐，词嵌入与输出头可以逐字节继承。其二，家族特异性一处维护：Qwen3 与 Gemma 的结构差异全部由各自家族的转换器模块承担，草稿代码只写差异部分。其三，配置即文档：从草稿配置能完整还原"它是从哪个目标派生的、抽了哪几层、块多长"，与第八章的配置快照机制配合，任何检查点都可以精确重建。

层取点是派生配置里最重要的专有字段。校验函数要求层号非空、严格递增、且落在合法范围（负一有特殊含义，表示词嵌入输出层，允许 DSpark 使用而 Eagle3 不允许——后者只消费解码层）。递增约束同时固定拼接顺序，保证"第一个特征永远是浅层"这类结构先验在训练与评测间一致。取点位置按家族区分：三十六层的 Qwen3 取一、九、十七、二十五、三十三，四十八层的 Gemma 取五、十七、二十九、四十一、四十六，两组取点都近似等距铺满深度轴。等距不是美学偏好而是信息论取向：多层特征的目的是让草稿同时看到词法、语义与决策倾向，等距采样以最少的层覆盖最大的表征变化。

## 5.2 DSpark 前向的完整数据流

Qwen3 版 DSpark 模型（deepspec/modeling/dspark/qwen3/modeling.py）的一次训练前向是一条清晰的双流管线。第一条流是目标上下文流：从缓存载入的目标多层隐状态经跨注意力的键值投影进入草稿各层，充当草稿的"外部记忆"；第二条流是草稿自身流：输入嵌入由两部分拼成——锚点词元的真实嵌入与块内占位标记的嵌入（由掩码标识构造占位，这个标识是家族专属的：Qwen3 词表里是十五万一千六百六十九号，Gemma 词表里是四号），两者沿序列维拼进草稿的词元嵌入流。草稿解码层对这两条流做拼接注意力：查询来自草稿隐藏态，键值来自目标上下文与草稿自身的并集。

块内并行预测的核心在于：七个草稿位在注意力上互为可见（第二章掩码规则之二），一次前向同时出七份分布。输出容器是声明式数据类 DSparkForwardOutput，装载草稿分布（已含马尔可夫修正）、监督标签、逐位评测掩码、逐块保留掩码，以及可选的置信度预测与目标对齐分布。容器即契约：损失函数只从容器取数据，前向的任何重构只要保住容器的语义就不破坏损失。

位置编码沿绝对位置：每个草稿位的位置标识等于锚点位置加块内偏移，与目标上下文的位置空间连续，草稿的旋转编码表直接复用目标家族的实现。这意味着草稿天生理解"我在预测序列中的第几号词元"，无需额外教学。Gemma 版在此基础上还有一个家族特例：Gemma 的词嵌入是缩放嵌入（嵌入值乘以隐藏维的平方根），草稿用家族提供的缩放嵌入类保持一致。

## 5.3 Gemma 骨干的四点结构差异

Gemma 版 DSpark（deepspec/modeling/dspark/gemma4/modeling.py）与 Qwen3 版同构，但注意力与归一化有四处家族差异，文件头注释把它们概括为"缩放为一的查询键值归一化、键值等价变体、四归一化层与对数几率软上限"。逐条展开。第一，Qwen3 的注意力缩放因子是头维平方根的倒数，Gemma 不在注意力内部缩放，尺度控制全部交给查询与键各自的归一化层——数值稳定性的责任从"先缩放后归一化"转移到"归一化自带尺度参数"。第二，值向量也有独立的均方根归一化（无缩放变体），Qwen3 没有；值向量的分布稳定性对块内并行的草稿尤其重要，因为草稿键值在推理时会被反复裁剪重算（第十章的裁剪循环），归一化前置可以减少裁剪边界处的分布突变。第三，家族支持键值等价的注意力变体：开启时值投影被整个省略，值直接复用键——这既是参数与显存的节省，也是该家族预训练分布的一部分，草稿必须原样继承，否则继承来的权重落在错误的函数族上。第四，输出头的对数几率经软上限函数压缩（双曲正弦乘上限系数），限制 logits 的幅值；蒸馏损失对齐的是上限之后的分布，草稿的输出路径同样要经过软上限，两边才在同一坐标系里比较。

"四归一化层"指块内的归一化次数：前置归一化两次（注意力前与前馈前）加后置两次（两支路的残差相加前），构成三明治结构。草稿的归一化层独立于目标（训练器注释明确：头部不训练、归一化不继承——继承来的是在更深网络上校准过的尺度，搬到浅层草稿反而有害），只有词嵌入与输出头逐字节继承并冻结。

## 5.4 Eagle3 草稿：单层主干与双流输入

Eagle3 草稿（deepspec/modeling/eagle3/qwen3/modeling.py）的结构在第二章已概述，这里补实现细节。输入融合是一个低秩投影：五个目标层的隐状态拼接后维度是隐藏维的五倍，投影层把它压回草稿隐藏维，与当前词元嵌入拼接成双流输入。融合投影是草稿唯一"新学"的特征变换，它的初始化与学习率继承整体训练配置；五层特征的权重全部交给它学习，这是"特征拼接交给投影"对"手工加权"的替代。解码主干只有一层，沿用家族结构（分组查询注意力、查询键归一化、前置归一化），注意力实现走弹性注意力入口以配合展开掩码。输出头同样继承自目标并冻结，词表维的输出投影不占训练参数。

训练时的递归展开（TTT）在实现上表现为"同一次前向内多轮滚动"：每轮把上一轮的输出词元左移一位作为下一轮输入（补零函数完成移位），键值缓存按轮追加，展开七轮共产生七轮的预测分布与七份蒸馏损失。轮次间共享同一套层权重——单层主干反复使用七次，参数量与推理开销都保持极小。这里能看到 TTT 范式的本质：训练时把"推理时的循环"搬进"训练时的图"，用展开换梯度。

编译配置是单层主干之外的性能细节：弹性注意力的块稀疏掩码每多缓存一轮就换一次形状，每次换形触发一次重编译，训练器启动时把编译缓存上限抬到六十四（configure_eagle3_flex_compile），否则长训练会反复掉回慢速执行路径。Qwen3 版 DSpark 的配置开启整体图编译，Gemma 家族则关闭——差异来自家族模块对编译追踪的兼容性，配置注释里写明了这个归属。

## 5.5 评测与训练的注意力实现分野

草稿模型在训练与评测使用不同的注意力实现，且差异是刻意为之。训练期固定用弹性注意力（两个家族的配置构造都把训练注意力实现钉死在该选项上），因为它需要块稀疏掩码的表达力——DSpark 的锚点掩码与 Eagle3 的展开掩码都不是矩形掩码，弹性注意力以掩码函数编译出跳过全屏蔽块的内核，是唯一同时具备表达力与效率的选择。评测期统一用缩放点积注意力（评测器类属性 EVAL_ATTN_IMPLEMENTATION 取 sdpa）：评测的注意力形态是标准的因果加缓存增量，矩形掩码即可表达，该实现路径最稳、最快、且行为与推理引擎的常见实现一致，保证测得的加速比可迁移。

两种实现的数值不可比也不必比：弹性注意力的掩码函数在同一查询键对上的判定与显式掩码张量逐位一致，差异只在执行策略。分野的原则可以总结为"训练要表达力，评测要保真度"——训练期的掩码是为梯度正确性服务的结构，评测期则要模拟真实部署路径。第十章的评测循环会再次回到这一点。

## 5.6 模型对象与训练器的接合

模型类的最后一层职责是与训练器的接口约定。两个训练器（Qwen3DSparkTrainer 与 Qwen3Eagle3Trainer，见 deepspec/trainer/ 目录）各自声明数据整理器类与草稿构建函数：DSpark 训练器的构建函数按家族分派到两个配置构造器与两个模型类，Gemma 版训练器只覆写构建函数、完全复用训练循环——家族差异被压缩到"构建哪套类"这一行。训练步的实现（run_batch）展示了模型对象的消费面：输入词元、目标多层隐状态、损失掩码与目标末层隐状态四件套进前向，输出的容器交给损失函数（下一章的主角），返回标量损失。Eagle3 训练器重写模型构建的原因是继承头部需要目标权重：把目标模型加载到处理器上只为取两个矩阵，取完即弃。整个接合面保持最小：训练器知道容器与损失函数的签名，模型知道家族结构，配置知道超参——三者以数据类的字段名解耦，任何一个的内部重构都不波及其余。下一章就沿着这条接合面进入损失函数的内部。

## 5.7 弹性注意力的编译视角：掩码即程序

块稀疏掩码的构造函数值得从"编译"的角度再看一遍，因为它代表了一种与显式掩码张量截然不同的思维方式。传统做法是构造一个与查询键对同形的布尔张量，注意力内核逐位读取——四千乘八千的对数几百万个布尔值，掩码本身的显存与带宽不可忽略。弹性注意力的做法是把掩码表达为一个纯函数：给定批、头、查询下标与键下标，返回可见与否。内核在编译期把这个函数编译成块级调度——整块全屏蔽的直接跳过，块内再逐位判定——掩码的存储从"与注意力同形的张量"压缩为"函数加少量元数据"。DSpark 掩码函数的三条规则（防泄漏、定块内、除噪声）与 Eagle3 掩码的因果加对角两项，都以这种函数形式书写；函数体内只允许依赖捕获的少量张量（锚点位置、逐块保留掩码、有效长度），这是块级调度的前提。头维共享（掩码与头无关，构建时头数传空）让掩码元数据再省一档。

这套表达力的代价是编译复杂度：掩码函数的每次形状变化都触发重编译，第九章提过的编译缓存上限调整（Eagle3 展开训练每多缓存一步就换一次掩码形状）正是为对冲这个代价。训练期钉死弹性注意力（第五章第五节）的另一半原因也在此：掩码函数一旦写好，块稀疏的算力节省是白拿的。

## 5.8 位置编码与缓存裁剪的相互作用

草稿的键值缓存在推理期被反复裁剪（第十章的裁剪循环），位置编码与裁剪的相互作用是正确性的隐蔽角落，值得展开。草稿缓存里的每条键值都带着自己被写入时的位置信息（旋转编码在写入时施加），裁剪只删除键值、不重排位置；下一轮提案的新位置从缓存当前长度顺延（位置标识按缓存长度到起点加块长切片），因此"裁到提交长度、从提交长度续写"保证了位置的连续性——新块的首位恰好接在已提交序列的末位之后，旋转相位无缝衔接。若裁剪与提交不一致（多裁或少裁一个词元），新块的位置相位整体错位，旋转编码的相对关系被破坏——输出分布在工程上就已经偏离目标分布，而这一切没有任何报错。评测代码里"前向退出前裁回起点"与"提交后裁到新起点"的两处裁剪，正是这套约束的执行点。位置连续性因此与第一章的分布无损性并列，成为裁剪逻辑的两条硬约束。

## 5.9 两份缓存的生命周期

草稿推理涉及两份键值缓存，生命周期截然不同，混为一谈会出隐蔽错误。目标缓存承载已验证序列的上下文：验证前向写入整段草稿位的键值，提交后裁到新起点——它的内容永远是"已提交序列的真值前缀"，跨轮存活。草稿缓存承载草稿自己的起草上下文：块前向写入整块的键值，验证采纳多少取决于目标，未采纳部分在退出前即裁回起点——它的内容是"本轮提案的临时状态"，跨轮只保留已提交前缀对应的部分。两份缓存的裁剪点不同：目标缓存裁到提交后长度，草稿缓存裁到本轮起点（裁剪动作甚至发生在块前向的退出处，因为提案构造已经取走了需要的隐状态）。缓存的这种纪律与投机解码的语义同构：草稿的猜想在被目标盖章之前，不配拥有持久状态。

## 5.10 参数清单：哪些是新学的，哪些是继承的

把草稿模型的参数按来源列一张清单，能一并回答"模型多大、学什么、冻什么"。继承且冻结的：词嵌入与输出头（与目标逐字节相同，加载后立即设为不可训练，恢复后重冻结）。新初始化且训练的：草稿解码层的全部参数（一到五层）、多源特征的低秩融合投影（Eagle3）、跨注意的键值投影与主干（DSpark）、马尔可夫头的两个低秩矩阵、置信度头的单层线性。独立不继承的：全部归一化层（第五章第三节的理由）。这份清单直接决定优化器状态与梯度的显存预算（第七章的账）：可训练参数只有亿级的新增层，继承的十亿级嵌入不占梯度与优化器状态——这也是草稿能用六百四十万分之一的学习率预算在数十万步内训完的原因之一：它学的不是语言，是"在目标特征上起草"这一件小事。

## 5.11 两个家族的差异总表

把 Qwen3 与 Gemma 两个家族在草稿侧的全部差异汇总成表，方便对照第五章前文：

| 差异项 | Qwen3 版 | Gemma 版 |
| --- | --- | --- |
| 词嵌入 | 普通查表 | 缩放嵌入（乘隐藏维平方根） |
| 注意力缩放 | 头维平方根倒数 | 不缩放，交给查询键归一化 |
| 值归一化 | 无 | 独立均方根归一化（无缩放） |
| 键值等价变体 | 无 | 可开启，省略值投影 |
| 归一化布局 | 前置两次 | 前后各两次（三明治） |
| 输出头 | 直接线性 | 对数几率软上限 |
| 对话模板 | 经典助手段格式 | 模型轮次加思考通道前缀 |
| 图编译 | 开启 | 关闭 |

这张表也是"家族差异封装在模型层"主张的证据：八项差异没有一个泄漏到训练循环、损失函数或数据管线，配置文件里与家族相关的只有模板名、占位标识、层取点与编译开关四个字段。

## 5.12 派生配置的实现细节补遗

派生式配置还有三处细节值得补记。其一，层类型的显式声明：派生时把草稿每层的注意力类型都声明为全注意力——草稿不做滑动窗口，块内自注意加跨注意需要完整视野，这一声明同时决定了旋转编码的作用范围。其二，注意力实现的钉死：派生配置把训练期注意力实现固定为弹性注意力（字符串常量），评测期的实现由评测器类属性另行指定——两处常量分居训练与评测两侧，各管各的路径。其三，校验的时机：层取点的范围与递增校验、置信度头配置的配套检查（开置信度头必须声明其输入协同开关）都发生在派生函数内，配置错误在模型构建时爆炸，而不是训练若干步后以诡异行为呈现。"越早失败越好"在这里的具体含义是：把所有跨字段的约束检查放进唯一的派生入口。

## 5.13 输出容器的形状语言

DSpark 前向输出容器的每个字段都以形状注释定义，把这组形状翻译成"语言的读法"有助于读训练与损失代码。草稿分布是四维张量：批、锚点块、块内位置、词表——它回答"每个锚点之后的七个位置各是什么分布"。监督标签是三维：批、块、位——锚点之后的真实词元，逐块对齐。逐位评测掩码与标签同形：连续使能前缀的语义在形状上不可见，只在取值上可见。逐块保留掩码是二维：批、块——哑块的标记。置信度预测与标签同形（每位的标量），目标对齐分布与草稿分布同形（供蒸馏逐位对齐）。形状语言的一致性让损失代码几乎不需要注释：两个张量可逐位相乘当且仅当它们语义对齐，四维分布与三维标签在词表维做交叉熵当且仅当监督关系成立。读模型代码的第一课就是读形状——形状对了，语义大概率是对的。

## 5.14 占位嵌入的设计动机

块内除首列外的占位标识值得单独讨论动机。块状并行的一个本质困难是：七个位置一次前向，但第 k 位"应当"依赖前 k 减一位的采样结果——这个依赖在训练期被教师强制（前驱取真值标签，经马尔可夫头注入），在结构上则表现为"所有位置同时存在、彼此可见"。占位标识的角色是给这些"同时存在"的位置一个统一的、可学习的输入身份：它们告诉草稿"这个位置是被并行预测的对象"，让草稿把块内位置与真实上下文词元在输入侧就区分开。占位词元的选择（家族词表中真实存在且罕见的编号）保证嵌入查表有预训练的初始值——从零初始化的特殊标识也能工作，但复用一个罕见词元的嵌入让输入分布在微调起点上更接近预训练分布。占位设计与第二章的注意力规则（块内全可见）、第六章的马尔可夫修正（前驱偏置）共同构成块状并行的完整输入侧方案：身份用占位表达，依赖用偏置表达，边界用掩码表达。

## 5.15 对数几率的坐标系一致性问题

蒸馏损失的隐含前提是两个分布在同一坐标系里比较，这个前提在带输出变换的家族里需要显式维护。Gemma 家族的输出头在对数几率上施加软上限（双曲正弦乘系数）：目标模型的实际输出分布是上限后的分布，缓存里的监督信号（末层隐状态加继承的输出头）也按上限后计算；草稿的输出路径必须经过同样的软上限，两边才在同一坐标系——若草稿跳过上限，蒸馏会把"上限前的无界值"对齐到"上限后的有界值"，梯度方向系统性错误。Qwen3 家族无上限，坐标系天然一致。这个细节的推广教训是：任何"继承目标的头部"的设计都必须逐一核对头部的全部变换（缩放嵌入、上限、归一化），继承的是整个函数而不只是权重矩阵——第五章第十一节的差异表里每一行，都是坐标系一致性的检查项。

## 5.16 Eagle3 展开步与缓存块的形状对应

Eagle3 训练掩码的分块布局（第二章第二节）值得从形状对应的角度再走一遍，因为它是"训练图模拟推理循环"的精确注脚。设序列长为整条训练序列、展开步数为七：缓存里第 s 块承载第 s 步展开的全部位置的键值，块内第 i 个槽位对应原始第 i 个词元。第 s 步的查询（槽位 i）在真实推理时应能看到：原始前缀（词元一至 i 加 s 减一）的各步草稿键值——掩码的两项（对最旧块的因果项加对后续各块的对角项）恰好把这两个集合拼出来。形状对应的正确性可以直接验证：对任意查询，其可见键值集合中每个元素都映射到唯一的原始词元，且全部可见的原始词元构成连续前缀——这正是推理时草稿缓存的因果前缀性质。把推理的循环性翻译成训练的块状性，代价是掩码函数的两项结构；收益是七步展开并行成一次前向——TTT 范式的全部技巧浓缩在这一张形状对应表里。

## 5.17 草稿的推理成本模型

给两种草稿结构建立一个粗但够用的推理成本模型，用于解读评测结果。Eagle3 的起草成本是逐步的：每步一次单层前向（参数量小但访存固定），提案 k 个词元要 k 次小前向加 k 次缓存追加；其单步成本主要受词表投影（输出头在每步都要算全词表对数几率）支配。块状系的起草成本是一次性的：五层前向一次完成，输出头只算一次整块；其成本随块长近似线性但常数被并行摊薄。把两个模型代进第一章的加速比公式：Eagle3 在小提案长度时占优（单步开销小），块状系在大提案长度时占优（并行摊销）——交叉点由"输出头成本对主干成本之比"决定，词表越大的模型交叉点越靠左（输出头越贵，逐步算越不划算）。这个模型还解释了置信度截断的成本结构：截断节省的是验证与草稿双方的成本，而置信度头自身的成本（单层线性）在两种结构里都可忽略——成本模型是理解"哪些优化值得做"的天平。

## 5.18 结构选型的决策树

把本章与前两章的结构知识收成一棵选型决策树，供实际决策时走查。第一问：部署形态是单请求时延敏感还是批量吞吐敏感？前者进入第二问，后者倾向块状系（并行起草的摊销优势）。第二问：草稿要跨领域泛化还是深耕单一领域？跨领域倾向五层主干加多层特征（容量换泛化），单一领域一层主干也可能够用（Eagle3 的极简路线）。第三问：提案长度需求长不长？长提案（块长七以上）必须补块内依赖——块状系配马尔可夫头，或直接走递归展开。第四问：能否接受置信度头的校准维护成本？能则选 DSpark 形态（长度自适应），不能则固定块。第五问：目标家族是哪个？确定模型层实现与占位标识（第五章的家族差异表）。决策树的每片叶子都对应 config 目录下某个现成配置的修改版——选型的终点不是发明配置，而是找到最近的配置改两个字段。

## 5.19 模型代码的阅读路线

给准备精读模型实现的读者一条由浅入深的阅读路线。第一站：公共工具层（两个算法各自的 common 文件）——读输出容器、特征抽取与掩码函数，建立形状语言（本章第十三节）与可见性规则（第二章第五节）。第二站：配置构造（各家族的 config 文件）——看目标配置如何派生、校验在哪里发生（本章第十二节）。第三站：骨干模型（qwen3 目录的 modeling）——沿前向的调用链读：嵌入、层循环、输出头，对照第九节参数清单确认继承与新建的边界。第四站：家族差异（gemma4 目录）——带着第十一节差异表读，逐项找到实现位置。第五站：修正头与损失（markov 头文件、两个损失文件）——回到双路径与三项损失的原理（第二章、第六章）。路线的顺序设计是"先接口后实现、先共享后特化"：读完前三站就能读懂训练循环对模型的使用，读完五站则具备了写第四种算法模型层的全部背景（第十二章的贡献路径）。

## 5.20 与模型生态的接口面

草稿模型与开源模型生态的接口面保持得极窄而清晰，值得作为设计范例记录。输入面：目标模型以标准接口加载（自动配置与自动模型类），家族结构全部来自生态维护的建模代码——目标模型的升级（新版本、新家族）自动可用，草稿侧只需新增派生配置。输出面：草稿检查点以标准格式保存（第八章），任何标准加载器可读——评测脚本、推理引擎、发布平台都按同一接口消费。配置面：草稿配置是目标配置的深拷贝加自有字段，架构字段（模型类名）随检查点保存并被评测路由消费（第十章）。接口面的窄带来两个性质：依赖锁定最小（生态 API 变化时改动集中在加载点）、双向兼容自然（上游家族更新与下游检查点消费互不阻塞）。第五章的派生式设计在生态层面的意义正在于此：草稿不重新发明模型，它寄生在生态的建模代码上，只维护自己的增量。

## 5.21 读模型代码的形状断言习惯

给精读者一个具体的阅读技巧：把形状当作断言来读。模型代码里的每个张量操作都隐含一个形状断言（拼接沿哪一维、广播向哪一维、切片保留哪些维），阅读时有意识地把这些断言写出来（纸边或注释），两页之后整个前向就变成一张可验证的形状流图——任何一处语义误解都会在形状流图上表现为"维度对不上"。本章第十三节的容器形状语言是这张图的节点，操作序列是边。这个技巧对块稀疏掩码代码尤其有效：掩码函数的输入输出都是下标（批、块、位的三重换算），换算链条逐行验证是读懂三条可见性规则的最快路径。形状断言习惯的深层价值是把"读懂了"变成"可以验证地读懂了"——与第六章把损失推导对照到代码逐行、第八章把状态清单对照到存档字段是同一种工程阅读法：阅读的目标不是复述，而是能对拍。

## 5.22 本章速览

本章的骨架四句话：草稿是目标家族结构的派生体，派生保证了词表与结构的逐字节兼容；两种起草哲学（投影拼接与跨注意注入）适配两种主干厚度，家族差异全部封装在模型层；两份缓存的生命周期纪律（目标存真值前缀、草稿存临时猜想）与位置连续性是无损性的工程前提；参数清单（继承冻结的嵌入与头、新建的层与头、独立不继承的归一化）直接决定显存账与学习内容。第五章是全书唯一深入张量与形状细节的一章——它存在的理由是：模型层的每个设计决定都会以静默的方式影响接受率，静默的影响只有形状级的审读才能发现。
